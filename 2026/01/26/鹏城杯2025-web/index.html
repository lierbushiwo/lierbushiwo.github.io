ezDjango

先认识一下Django的项目结构

先看主路由/app/urls.py

  • 把admin路由给django自带的后台管理系统
  • 接下来把其他路由映射给cacheapp.urls

接下来看/cacheapp/urls.py

对应处理逻辑/cacheapp/views.py

接下来就是审计了，看站点的各个功能逻辑

突破点在这,从 Django 的缓存系统中获取数据,Django 缓存框架在内部处理数据时，会使用 pickle 模块对 Python 对象进行序列化，将对象转换为字节流存储,读取时自然有pickle.loads()的操作,文件格式为Django缓存文件格式

Django缓存文件格式：pickle.dumps(过期时间) + zlib.compress(pickle.dumps(值))

缓存文件名计算：

Django会给key添加前缀，格式：:版本:key
默认版本为1，所以pwn → :1:pwn
文件名 = md5(":1:pwn").hexdigest() + ".djcache"

思路

  • 向/tmp目录上传lier.cache
  • 把/tmp/lier.cache移动到/tmp/django_cache/{cache_file}下
  • 通过cache/trigger/路由触发 cache.get(key, None) key=pwn

在/app/settings.py查看缓存文件目录
